## 摘要
时间序列预测的最新进展日益依赖于预训练的基础模型。尽管这些模型通常声称具有广泛的泛化能力，但现有的评估协议提供的证据有限。事实上，目前大多数基准测试使用静态的训练-测试集划分，这很容易导致数据污染，因为基础模型可能会无意中在测试数据上进行训练，或者利用测试分数进行模型选择，从而虚增性能。我们推出了 Impermanent，这是一个实时基准测试，通过在持续更新的数据流上按时间顺序对预测进行评分，评估预测模型在开放世界时间变化下的表现。它能够研究时间鲁棒性、分布偏移和性能稳定性，而非仅关注冻结测试集上的单次准确率。Impermanent 基于 GitHub 开源活动进行实例化，提供了一个天然实时且高度非平稳的数据集，其特征受版本发布、贡献者行为转变、平台/工具变更以及外部事件的影响。我们关注 Star 数量排名前 400 的仓库，并根据已开启的 Issue、已开启的 Pull Request、Push 事件和新增 Stargazer 构建时间序列，通过每日更新的滚动窗口进行评估，并提供标准化协议和排行榜以进行可重复的持续对比。通过将评估重点从静态准确率转向持续性能，Impermanent 在评估时间序列预测中基础级泛化能力何时以及是否可以被有意义地声称方面迈出了坚实的一步。代码和实时仪表板可在 https://github.com/TimeCopilot/impermanent 和 https://impermanent.timecopilot.dev 获取。

## Abstract
Recent advances in time-series forecasting increasingly rely on pre-trained foundation-style models. While these models often claim broad generalization, existing evaluation protocols provide limited evidence. Indeed, most current benchmarks use static train-test splits that can easily lead to contamination as foundation models can inadvertently train on test data or perform model selection using test scores, which can inflate performance. We introduce Impermanent, a live benchmark that evaluates forecasting models under open-world temporal change by scoring forecasts sequentially over time on continuously updated data streams, enabling the study of temporal robustness, distributional shift, and performance stability rather than one-off accuracy on a frozen test set. Impermanent is instantiated on GitHub open-source activity, providing a naturally live and highly non-stationary dataset shaped by releases, shifting contributor behavior, platform/tooling changes, and external events. We focus on the top 400 repositories by star count and construct time series from issues opened, pull requests opened, push events, and new stargazers, evaluated over a rolling window with daily updates, alongside standardized protocols and leaderboards for reproducible, ongoing comparison. By shifting evaluation from static accuracy to sustained performance, Impermanent takes a concrete step toward assessing when and whether foundation-level generalization in time-series forecasting can be meaningfully claimed. Code and a live dashboard are available at https://github.com/TimeCopilot/impermanent and https://impermanent.timecopilot.dev.

### 1. 核心问题与研究动机
*   **核心问题**：当前时间序列预测模型的评估主要依赖于**静态数据集**（如 GIFT-Eval, Monash 等）。这种方式存在两个致命缺陷：
    1.  **数据污染（Contamination）**：基础模型在预训练阶段可能已经见过测试集数据，导致性能虚高。
    2.  **缺乏时间泛化评估**：静态切分无法衡量模型在面对现实世界中不断演变的非平稳分布（如趋势变化、突发事件）时的持续表现。
*   **研究动机**：建立一个“活的”基准，通过在真实世界持续产生的数据流上进行序列化评分，验证模型是否具备真正的**时间泛化能力**（Temporal Generalization）。

### 2. 方法论
*   **核心思想**：采用**预序评估协议（Prequential Evaluation）**。模型必须在真实观测值产生之前提交预测，预测结果在数据到达后才进行评分。
*   **关键技术细节**：
    *   **数据源**：利用 GitHub Archive 提供的实时事件流，追踪 400 个热门仓库的四类活动：开启 Issue、开启 PR、Push 事件、新增 Star。
    *   **非平稳性刻画**：通过频谱质心（Spectral Centroid）和频谱熵（Spectral Entropy）量化数据的动态变化，证明 GitHub 数据包含从平滑趋势到剧烈波动的多种模式。
    *   **评估流程**：在每个截止日期（Cutoff），为模型提供历史观测窗口，要求预测未来 $h$ 个周期的点预测和概率分布。
    *   **指标计算**：使用 **MASE**（平均绝对等比例误差）衡量点预测准确性，使用 **scaled CRPS**（缩放连续排位概率分数）衡量概率分布质量。所有指标均相对于“零预测模型”进行缩放，以实现跨数据集的可比性。

*   **对比方法（共 12 种）**：

    *   **基础模型（TSFMs）**：Chronos-2、Moirai 2.0-R-Small、TimesFM 2.5、TiRex。
*   **Benchmark 形式**：提供实时更新的在线排行榜，记录模型随时间推移的排名稳定性。

### 6. 主要结论与发现
*   **基础模型占优**：在初步快照中，TimesFM、TiRex、Moirai 和 Chronos 等基础模型占据了前四名，证明了大规模预训练的优势。

*   **排名波动**：由于环境的非平稳性，模型排名并非固定不变，这强调了持续评估的重要性。

*   **防污染设计**：实时数据流确保了测试数据对模型是绝对新鲜的。

*   **领域局限性**：目前仅限于 GitHub 软件开发活动数据，虽然具有代表性，但不能完全代表金融、气象等所有领域。
